## План доработки ФЛАГМАН

Объём большой, поэтому предлагаю разбить на этапы. Подтвердите подход — особенно по админ-панели, так как она требует ключевых решений.

### Этап 1. Быстрые исправления и контент (без бэкенда)

1. **Мобильный футер** — переработать `Footer.tsx`: вертикальная компоновка на мобильных, кнопка «Купить игру» отдельной строкой, не наезжает на e-mail.
2. **Ссылка «Где купить»** — добавить в шапку (уже есть `/buy`, проверить видимость в `Header.tsx` на мобильных).
3. **Slug на английском для стран** — переработать `src/lib/countries.ts`: ввести поле `slug` (germany, france, brazil, japan…). Маршрут `/flags/$code` → `/$slug` (плоские URL `flagman.games/germany`, как просили). Старый `/flags/:code` оставлю редиректом, чтобы не сломать ссылки.
4. **Расширенный контент стран** — добавить поля: `phoneCode`, `government`, `religions`, `foundedDate`, `historyShort`, и для предыдущих флагов — `dateAdopted`, `yearsUsed`, `differences`. Заполню для ~20 стартовых стран; структура готова под массовый импорт.
5. **Каталог `/flags`** — оставить как индекс с фильтрами, ссылки ведут на `/germany` и т.д.
6. **Страница `/rules`** — переписать по вашему тексту: суть, простая, сложная версии, блок «Кто станет Флагманом», CTA-баннер «Считайте очки онлайн» → `/score`.
7. **Страница `/full_rules`** — новая, `noindex,nofollow`, без линков из меню/футера/сайта. Содержит копию `/rules` + подробное описание всех типов карт (флаги, пиратские, белый флаг, смена курса, континенты, олимпийский, революция, Флагман, «Все на Марс») с якорным меню и адаптивом.
8. **`/buy`** — карточки Ozon / Wildberries / Avito с описанием и кнопками. Ссылки пока в конфиге (`src/lib/site-config.ts`), позже редактируются через админку.
9. **SEO** — `head()` на новых маршрутах, обновить `sitemap.xml` (без `/full_rules`), `robots.txt` явно запрещает `/full_rules`.

### Этап 2. Админ-панель — нужны решения от вас

Полноценная CMS с редактированием всех страниц, картинок, SEO и slug требует бэкенда. Варианты:

**A. Lovable Cloud (рекомендую)** — встроенная БД + auth + хранилище картинок. Один логин-админ, страницы и страны хранятся в таблицах, фронт читает оттуда. Полностью под ваш контроль, без внешних аккаунтов. Это правильный путь для долгоживущего проекта.

**B. Sanity / Strapi (внешний headless CMS)** — мощнее визуально, но требует регистрации и настройки на их стороне.

**C. Git-based (контент в JSON-файлах, редактирование через простой UI в админке, который коммитит в репо)** — без БД, но требует деплоя на каждое изменение и менее удобно.

Если выбираем **A**, то реализую:
- включение Lovable Cloud;
- таблицы: `pages` (главная, о проекте, контакты, FAQ, юр.), `countries`, `previous_flags`, `marketplaces`, `faq_items`, `footer_settings`, `seo_meta`;
- роль `admin` через `user_roles` + `has_role()`;
- маршрут `/admin` с логином, списком сущностей, формами (заголовок, подзаголовок, текст, картинки через storage, кнопки/ссылки, SEO title/description, slug);
- импорт стран из CSV/JSON;
- фронт переключается на чтение из БД (server functions с RLS).

Это отдельный большой этап (≈столько же работы, сколько весь сайт сейчас).

### Технические детали

- Маршруты стран: `src/routes/$slug.tsx` (catch-all для корня неудобен — конфликт с `/about`, `/buy` и т.д.), поэтому правильнее `src/routes/country.$slug.tsx` с URL `flagman.games/country/germany`. **Уточните: настаиваете на `flagman.games/germany` без префикса?** Это решаемо через явный whitelist в loader, но усложняет роутинг и риск конфликтов при добавлении новых разделов.
- `noindex` на `/full_rules`: `<meta name="robots" content="noindex,nofollow">` через `head()` + запись в `robots.txt`.
- Картинки предыдущих флагов: использую Wikipedia Commons URL до появления storage в админке.
